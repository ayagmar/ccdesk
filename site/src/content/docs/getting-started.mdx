ccdesk needs Node.js 22.19 or newer. Run it from the directory you want to look at:

```sh
cd ~/code/my-project
npx ccdesk
```

It starts a small server on `127.0.0.1`, opens your browser on the directory you ran it from, and prints the address:

```
ccdesk is running at http://127.0.0.1:41873/#token=…
Press Ctrl+C to stop.
```

The part after `#token=` is a key generated for this run. The page needs it to talk to the server, so open the printed address rather than typing the host and port by hand. Press <kbd>Ctrl</kbd>+<kbd>C</kbd> in the terminal to stop ccdesk.

## Options

```
npx ccdesk [options]                     Open the page in your browser
npx ccdesk scan [dir] --json             Print what Claude Code loads in dir, as JSON
npx ccdesk explain <file> [--dir <dir>]  Print what loads once Claude reads or edits file

  --port <n>            Port to listen on (default: a free port)
  --no-open             Print the URL instead of opening a browser
  --config-dir <path>   Claude folder to read, as CLAUDE_CONFIG_DIR sets it for Claude Code
                        (wins over $CLAUDE_CONFIG_DIR)
  --dir <dir>           For explain: the folder the session starts in (default: the current one)
  -h, --help            Show this help
```

With `--no-open`, copy the printed address into a browser yourself. If the port you ask for is taken, ccdesk says so and exits.

If you keep several Claude Code profiles, `--config-dir ~/.claude-work` reads that one, as starting Claude Code with `CLAUDE_CONFIG_DIR=~/.claude-work` would. The flag wins over the variable.

### Without the browser

`ccdesk scan` prints, as JSON, everything the page shows for a directory: instruction files, settings layers and the values in effect, permissions, hooks, MCP servers, memory and problems. It reads the directory you run it from, or the one you name. A script or another tool can use it to ask what Claude Code loads there.

```sh
npx ccdesk scan ~/code/acme-api --json > acme.json
```

`ccdesk explain` is the [When Claude touches a file](../what-claude-sees/#when-claude-touches-a-file) check in the terminal: it lists the path rules, skills and folder instructions that join the session once Claude reads or edits a file. The session starts in the current directory, or in the one `--dir` names.

```sh
$ npx ccdesk explain src/api/users.ts
Once Claude reads or edits src/api/users.ts in ~/code/acme-api, these load:
  project  path rule            .claude/rules/api.md  matches src/api/**/*.ts
  project  folder instructions  src/CLAUDE.md
```

Both only read: they write no file and keep no backup. Values the page hides, such as env values and headers, are hidden in their output too.

## What it reads

ccdesk reads the same files Claude Code reads for the directory it is started in:

- your Claude folder, `~/.claude`, or `--config-dir` or `$CLAUDE_CONFIG_DIR` when one is set;
- `~/.claude.json` (or `.claude.json` inside that folder when it is not `~/.claude`), for folder trust, MCP servers and approvals;
- the managed settings folder your organisation may install: `/etc/claude-code` on Linux, `/Library/Application Support/ClaudeCode` on macOS and `C:\Program Files\ClaudeCode` on Windows;
- the directory you started in and every folder above it, for `CLAUDE.md`, `AGENTS.md`, `.claude/` and `.mcp.json`;
- transcripts in `~/.claude/projects/`, but only to count tool calls and your answers to permission prompts. See [Tool usage counts](../tool-usage/).

It never reads `~/.claude/.credentials.json`.

## What it writes

Nothing, until you review a change and press the button that saves it. Then ccdesk writes only the file the diff names: a settings file, a `.mcp.json`, a subagent file, a memory file or `MEMORY.md`. Before each write it copies the old file to `~/.claude/backups/ccdesk/`, and the change shows up in [Recent changes](../recent-changes/), where you can restore it.

ccdesk never writes `~/.claude.json`. Claude Code rewrites that file during every session. User and local MCP servers live there, so ccdesk changes them by running Claude Code's own `claude mcp` commands. See [MCP servers](../mcp-servers/).

## Live refresh

ccdesk watches the config files for the open directory. When Claude Code or your editor changes one, the page updates within about a second. `~/.claude.json` is not watched, because Claude Code rewrites it so often; the page rereads it when you switch back to the ccdesk tab. If ccdesk cannot watch a folder, the page names it above the tables. Changes elsewhere still show, ccdesk tries the folder again every few seconds, and the page rereads everything when you switch back to the tab. On Linux the usual cause is the limit on file watches; raise `fs.inotify.max_user_watches` with `sysctl`. A folder on a network drive is never watched.

## Other directories

The page opens on the directory you started in. The rail on the left lists every other directory Claude Code has been used in, and **All directories** shows them in a table with session and memory counts. You do not need to restart ccdesk to look at another project: pick it in the rail or press <kbd>Ctrl</kbd>+<kbd>K</kbd> and type part of its path.
